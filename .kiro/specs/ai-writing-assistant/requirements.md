# Requirements Document

## Introduction

This feature adds an AI writing assistant to the blog platform's post creation and editing form (`PostForm`). Authors can enter a natural-language prompt and receive a structured article — a title and rich-text content body — generated by an external LLM (e.g., OpenAI). The generated content is injected directly into the existing Title and Main Content fields, where the author can immediately review and edit it before publishing. The assistant must integrate cleanly into the existing `PostForm` state management without disrupting the current save/publish workflow.

## Glossary

- **AI_Assistant**: The client-side UI component embedded in `PostForm` that accepts a prompt and triggers content generation.
- **Generate_API**: The Next.js API route at `app/api/ai/generate/route.ts` that receives a prompt, calls the external LLM, and returns structured JSON.
- **LLM_Provider**: The external large-language-model service (e.g., OpenAI Chat Completions API) called by the Generate_API.
- **PostForm**: The existing React component (`components/posts/PostForm.tsx`) used for creating and editing blog posts.
- **RichTextEditor**: The existing Tiptap-based rich text editor component (`components/editor/RichTextEditor.tsx`) that renders the post's main content.
- **Prompt**: A natural-language string entered by the author describing the article they want generated.
- **GeneratedContent**: A JSON object with the shape `{ "title": string, "content": string }` returned by the Generate_API.
- **Author**: A user with the `author` role who is authenticated and has access to the post creation/editing form.

## Requirements

### Requirement 1: Prompt Input and Generate Button

**User Story:** As an author, I want to enter a prompt and trigger AI content generation from within the post form, so that I can quickly scaffold a new article without leaving the editor.

#### Acceptance Criteria

1. THE AI_Assistant SHALL render a text input field labelled "AI Prompt" within the PostForm, above the Title field.
2. THE AI_Assistant SHALL render a "Generate" button adjacent to the prompt input that submits the prompt to the Generate_API.
3. WHEN the prompt input is empty and the author activates the Generate button, THE AI_Assistant SHALL prevent submission and display the inline error message "Please enter a prompt before generating."
4. WHILE content generation is in progress, THE AI_Assistant SHALL display a "Generating…" label on the Generate button and disable the button to prevent duplicate submissions.
5. WHILE content generation is in progress, THE AI_Assistant SHALL disable the prompt input field to prevent modification of the in-flight request.
6. WHEN content generation completes or fails, THE AI_Assistant SHALL re-enable the prompt input and the Generate button.

---

### Requirement 2: AI Content Generation API

**User Story:** As an author, I want the platform to call a reliable AI backend, so that I receive a well-structured article in a consistent format.

#### Acceptance Criteria

1. THE Generate_API SHALL accept HTTP POST requests at `/api/ai/generate` with a JSON body containing a `prompt` field of type string.
2. WHEN a POST request is received with a non-empty `prompt`, THE Generate_API SHALL forward the prompt to the LLM_Provider and return a JSON response with the shape `{ "title": string, "content": string }`.
3. WHEN the `prompt` field is missing or empty in the request body, THE Generate_API SHALL return a 400 status code with the error message "Prompt is required."
4. THE Generate_API SHALL enforce a request timeout of 30 seconds when calling the LLM_Provider.
5. IF the LLM_Provider does not respond within 30 seconds, THEN THE Generate_API SHALL return a 504 status code with the error message "AI service timed out. Please try again."
6. IF the LLM_Provider returns a response that cannot be parsed as valid JSON matching `{ "title": string, "content": string }`, THEN THE Generate_API SHALL return a 502 status code with the error message "AI returned an unexpected response format."
7. IF the LLM_Provider returns an empty `title` or empty `content` field, THEN THE Generate_API SHALL return a 502 status code with the error message "AI returned an empty response."
8. THE Generate_API SHALL require the caller to be an authenticated user with the `author` role; unauthenticated requests SHALL receive a 401 response and requests from non-author roles SHALL receive a 403 response.
9. IF the LLM_Provider returns an error status, THEN THE Generate_API SHALL return a 502 status code with the error message "AI service error. Please try again."

---

### Requirement 3: Form Field Population

**User Story:** As an author, I want the AI-generated title and content to automatically populate the form fields, so that I can review and edit the result without manual copy-pasting.

#### Acceptance Criteria

1. WHEN the Generate_API returns a successful GeneratedContent response, THE AI_Assistant SHALL set the PostForm's title state to the value of `GeneratedContent.title`.
2. WHEN the Generate_API returns a successful GeneratedContent response, THE AI_Assistant SHALL set the PostForm's content state to the value of `GeneratedContent.content` and update the RichTextEditor to display that content.
3. WHEN generated content is injected into the PostForm, THE AI_Assistant SHALL preserve all other existing form field values (cover image, visibility status) without modification.
4. WHEN generated content is injected into the PostForm, THE AI_Assistant SHALL clear any pre-existing validation errors on the title and content fields.

---

### Requirement 4: Immediate Editability

**User Story:** As an author, I want to edit the AI-generated content immediately after it is injected, so that I can refine the output before publishing.

#### Acceptance Criteria

1. WHEN generated content has been injected into the PostForm, THE PostForm SHALL allow the author to freely edit the title input field.
2. WHEN generated content has been injected into the PostForm, THE RichTextEditor SHALL be in an editable state and accept author input.
3. THE PostForm SHALL treat AI-generated content identically to manually entered content for the purposes of validation and submission.

---

### Requirement 5: Error Handling and User Feedback

**User Story:** As an author, I want clear feedback when AI generation fails, so that I understand what went wrong and can take corrective action.

#### Acceptance Criteria

1. IF the Generate_API returns a 4xx or 5xx response, THEN THE AI_Assistant SHALL display the error message from the response body in an inline error area below the prompt input.
2. IF a network error occurs during the fetch to the Generate_API, THEN THE AI_Assistant SHALL display the message "Network error. Please check your connection and try again." in the inline error area.
3. WHEN a generation error is displayed, THE AI_Assistant SHALL not modify any existing PostForm field values.
4. WHEN a new generation request is submitted, THE AI_Assistant SHALL clear any previously displayed error message.
5. WHEN a generation error is displayed, THE AI_Assistant SHALL allow the author to correct the prompt and resubmit without requiring a page reload.

---

### Requirement 6: Non-Intrusive UI Integration

**User Story:** As an author, I want the AI assistant controls to feel like a natural part of the post form, so that the writing workflow is not disrupted.

#### Acceptance Criteria

1. THE AI_Assistant SHALL be visually contained within a clearly labelled section (e.g., "AI Writing Assistant") that is visually distinct but consistent with the existing PostForm design system (CSS custom properties and Tailwind classes).
2. THE AI_Assistant section SHALL be positioned above the Title field in the PostForm layout.
3. THE Generate button SHALL use a secondary or accent visual style that does not compete visually with the primary "Publish Post" / "Save Changes" submit button.
4. THE AI_Assistant SHALL not introduce any new third-party UI libraries beyond those already present in the project's `package.json`.

---

### Requirement 7: API Key Security

**User Story:** As a platform operator, I want the LLM API key to remain server-side only, so that it is never exposed to the browser.

#### Acceptance Criteria

1. THE Generate_API SHALL read the LLM_Provider API key exclusively from a server-side environment variable (e.g., `OPENAI_API_KEY`).
2. IF the `OPENAI_API_KEY` environment variable is not set at runtime, THEN THE Generate_API SHALL return a 500 status code with the error message "AI service is not configured." and SHALL log a descriptive error server-side.
3. THE Generate_API SHALL never include the LLM_Provider API key in any HTTP response body, header, or client-accessible location.
